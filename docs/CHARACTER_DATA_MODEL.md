# Character Data Model — M1

**Status:** implemented as the first versioned domain crate; host persistence adapter remains a later integration task.

## 1. Ownership

The `anicraft-360-model` crate owns persistent character-authoring semantics only. It does not own a second project file, renderer, timeline, VFS, undo system, animation evaluator, or deformation solver.

| Owner | Canonical data |
|---|---|
| AniCraft | Document identity, symbol IDs, bone IDs, Library folders, assets, persistence, commands, undo/redo, timeline and rendering |
| 360 Studio | Character parts, view sets, turn direction, authored views, landmark correspondence, Smart Bone authoring metadata, Switch Groups and asset references |
| Forma Deform | Controller definitions and evaluation, deformation targets/bindings, pin evaluation and deformation algorithms |

The model stores typed references to host-owned IDs. It never copies host bone/symbol objects or defines controller/deformation evaluation.

## 2. Persistent aggregate

`CharacterDocument` is the Studio extension aggregate for one host character. It contains:

- `CharacterPart`: stable Studio part identity, parent relationship, semantic role, optional AniCraft symbol reference.
- `ViewSet`: turn direction, zero-angle reference view, authored views and landmark tracks.
- `CharacterView`: stable identity, display name, normalized angle in degrees, optional host symbol reference.
- `LandmarkTrack`: one stable landmark identity with per-view normalized coordinates.
- `SmartBoneDefinition`: character-specific authoring metadata referencing a canonical AniCraft bone and optional Forma Deform ControllerId/target IDs.
- `SwitchGroup`: mutually exclusive symbol alternatives, optional host Library folder, view-set scope and explicit default option.
- `AssetReference`: typed role and canonical AniCraft asset ID.

The view rail is discrete. The data model does not imply interpolation or generated views.

## 3. Identity and coordinate rules

- Studio-owned entities use typed stable string IDs. IDs are supplied/generated by the host adapter; labels are never used as identity.
- AniCraft and Forma Deform IDs have distinct wrapper types to prevent accidental interchange.
- Turn angles are finite degrees in the half-open interval `[0, 360)`.
- Each ViewSet has one authored zero-angle view; each angle is unique within the configured epsilon.
- Landmark coordinates are normalized to the view bounds, origin at top-left, with finite `x` and `y` in `[0, 1]`.
- A landmark track is the correspondence identity across views; each position is keyed by a ViewId.
- Switch Group default options must refer to an option in the same group. A non-empty group must declare a default.
- Smart Bone trigger ranges use finite values with minimum strictly less than maximum. Controller IDs remain references, not controller definitions.

## 4. Validation

`CharacterDocument::validate` checks:

- Supported schema version and non-empty identity/name fields.
- Duplicate or empty IDs within each entity collection.
- Root and parent part references, self-parenting and hierarchy cycles.
- ViewSet zero-view references, unique view IDs, finite/ranged/unique angles.
- Landmark ID uniqueness, view references and normalized positions.
- Smart Bone names, trigger ranges, view-set references and affected-part references.
- Switch Group view-set references, option identity/symbol uniqueness, view membership and default-option membership.
- Asset reference identities and roles.

The model deliberately does not assert that host-owned symbols, bones, assets, controllers or deformation targets exist. The AniCraft adapter must resolve those references against the active document and Forma Deform capabilities.

Validation returns machine-readable issue codes and paths. Serialization refuses invalid documents.

## 5. Persistence and compatibility

- Current schema: `1`.
- JSON is the initial interchange/serialization representation for the Studio extension payload, not a replacement for AniCraft's project format.
- `to_json` validates before writing; `from_json` validates after reading.
- Unknown schema versions fail closed. No silent downgrade, data dropping or automatic interpretation of future fields.
- Future schema changes must add explicit, tested migrations before being accepted by the host persistence adapter.

## 6. Test coverage

The model crate tests cover valid round-trip serialization, unsupported schema rejection, invalid/duplicate turn angles, missing landmark views, out-of-range landmark positions, parent cycles, Switch Group default membership and the separation of external controller/target references.

Run:

```sh
cargo test -p anicraft-360-model
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

## 7. M1 exit criteria and remaining host work

The crate provides the versioned domain types, stable typed identities, cross-reference validation and JSON round-trip boundary. M1 is not fully integrated until AniCraft provides a versioned character-extension storage location and host commands for create/update/delete operations, with undo/redo and migration tests. The UI adapter must then project this aggregate into `StudioUiModel`; transient `StudioUiState` must remain outside the persistent document.
